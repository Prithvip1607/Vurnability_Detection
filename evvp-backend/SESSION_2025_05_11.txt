1. PHASE 3 — VERIFICATION ENGINE (pipeline/verifier.py)  [NEW]
   ─────────────────────────────────────────────────────
   Built the full Phase 3 verification engine. Every novel item that passes
   the pipeline now gets automatically verified. The verifier runs 4 checks:

   a) PoC Validator
      - Extracts GitHub repo URLs from item text/URL
      - Calls GitHub API to inspect the repo:
          · Checks file tree for exploit file extensions (.py, .c, .cpp, .sh, etc.)
          · Checks filenames for exploit keywords (exploit, poc, payload, shellcode)
          · Checks repo description for PoC keywords
          · Records star count as credibility signal
      - Falls back to text-based keyword matching if no GitHub URL

   b) Affected Product Extractor
      - 20 regex patterns extract vendor/product/version from title + text
      - Covers: Windows, Linux kernel, Apache, nginx, OpenSSL, Chrome, Firefox,
        VMware, Cisco, Palo Alto, Fortinet, Ivanti, Confluence, Exchange,
        SharePoint, Spring, Log4j, Kubernetes, Docker
      - Returns up to 10 distinct product strings

   c) Credibility Scorer (0-100)
      - Source reputation table: googleprojectzero=40, portswigger=30,
        unit42=25, microsoft=22, krebsonsecurity=20, r/netsec=18, etc.
      - Signal score contribution: score * 2, capped at 30
      - PoC found: +25
      - Cross-source confirmation: 3+ sources = +20, 2 sources = +10
      - NVD data attached: +15
      - CVE IDs present: +10

   d) Verification Status
      - confirmed  : credibility >= 70 AND (poc_found OR in_nvd)
      - likely     : credibility >= 45 OR (poc_found AND signal >= 14)
      - unverified : signal >= 8
      - noise      : everything else

   Output schema per item:
   {
     raw_id, poc_found, poc_signals, affected_products,
     credibility_score, credibility_notes, in_nvd, in_nvd_at,
     cross_source_count, verification_status, verified_at
   }

--------------------------------------------------------------------------------
  HOW THE FULL SYSTEM WORKS (end to end)
--------------------------------------------------------------------------------

1. You run: python3 main.py
   → _bootstrap() loads CVE mentions from disk, registers notifier callback
   → 4 ingestion workers start as daemon threads (reddit, github, blog, nvd)
   → API server starts on :8000

2. Each collector polls its source on its interval:
   Reddit  → every 5 min  → 12 subreddits
   GitHub  → every 10 min → 25 keyword searches × 3 types (repos/issues/commits)
   Blog    → every 15 min → 18 RSS feeds
   NVD     → every 1 hour → CVEs published in last 3 days

3. Every collected item goes through processor.py:
   [collect] → [signal score] → [NVD enrich] → [novelty check]
             → [store raw] → [store verified] → [VERIFY (Phase 3)]
             → [CVE track] → [notify if novel]

4. Phase 3 verification (for novel items only):
   → Check if GitHub URL has actual exploit code
   → Extract affected products from text
   → Score credibility 0-100
   → Assign status: confirmed / likely / unverified / noise
   → Save to intel_verification_results

5. CVE tracker watches for spikes:
   → 3+ mentions of same CVE in 6h = TRENDING
   → Fires Slack/Discord webhook + email alert

6. Frontend (npm run dev → :5173):
   → Proxies /api/* to :8000
   → Dashboard shows live pipeline stats
   → All Findings shows every stored item
   → Verified shows Phase 3 results
   → Trending shows CVE mention rankings
